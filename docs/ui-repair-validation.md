# Windows workspace repair validation

This local iteration integrates the compatibility, Bard, journal, notebook, holdings and companion work into verified Beta 1.6. It does not restore an older UI snapshot or publish a release.

## Results

- Complete core suite: **1,709 / 1,709**. This includes session aggregation, duplicate evidence, nullable values, scoped caps, equipment-point preservation, additive persistence and companion TLS/authentication/revocation checks.
- Native repair checks: **748 assertions**, including actual control bounds, accessible session/field names, independent Overview selection, stale work, normalized Save state, metadata/bookkeeping isolation, responsive sections and inline-link visibility.
- Existing native regressions: **110** toolbar checks, **44** Beta 1.6 checks, **51** Pet workspace checks, **41** summon/context checks, **139** independent-display checks and **11** standard-buff checks. Separate-process toolbar restart and real WPF Thumb capture/release ordering are covered.
- Companion preservation: **36** browser component/state checks and **6** Android protocol unit tests passed. Browser/Android screens and protocol remain unchanged.
- Package policy: five tests plus exact source-archive and runtime-tree assertions exclude local agent entry points, the shared guide, generated Android output and private/development content. No installer was rebuilt.

The affected Overview, Bard, source-notes and Phone controls were rendered at normal/minimum widths across Coldain, Sunstrider and Shadowman at 100%, 150%, 200% and 300%. Geometry and focus assertions accompany the captures. Expanded evidence and short-window scrolling retain accessible actions. The preview gallery contains selected actual WPF captures; screenshot count alone was not the acceptance criterion.

## Findings repaired

The previous feature candidate used retired Time scope/Fight presentation and placed recap inside encounter inspection. The repaired implementation preserves Beta 1.6's session-first Lab and adds a separate attached, read-only Overview. Session recap shortcuts and the inspector replacement are absent.

Workspace controls use 28-DIP bounds, toolbar buttons 24 DIP and shared disclosure focus reserves its border. Inline-only Overview links explicitly remain visible despite the shared empty-text style. Bard review uses compact gem rows, one evidence area and a potency disclosure; rank changes do not reuse exact component values from a different rank. Invalid/restored edits do not create false Save state. Source notes, optional holdings and compatibility conclusions use the shared presentation.

Equipment preference points remain separate from mechanical conclusions. Level 50 alone cannot establish the displayed 171 ceiling. Only a matching reviewed capture can supply that context; overhaste and hidden overflow remain unresolved. New evidence projection versions invalidate views without rewinding existing independent readers.

## Retained-data performance

The comparison used separate SQLite-backup copies of the same retained data: 688 encounters, 183,330 combat events, 42,665 healing events, 2,156 inventory observations and 4,676 ability outcomes. Originals were not benchmark targets.

| Measure | Verified Beta 1.6 | Repaired candidate |
|---|---:|---:|
| Routine UI P99 | 0.782 ms | 0.824 ms |
| Largest routine UI sample | 18.027 ms | 34.411 ms |
| CPU, percent of one core | 23.17% | 23.71% |
| Allocations during the 65-second run | 1,813 MB | 2,122 MB |
| Working set | 2,051 MB | 2,151 MB |

P99 remained below one millisecond; the 34-ms gear-phase outlier and approximately 17% higher allocations are retained for follow-up. These are isolated synthetic-window measurements, not live-game frame-rate claims. The final Bard-only editing correction was checked through the focused native editor regressions; it does not change the benchmark's closed-editor paths. Raw timing reports retain warm-up samples and outliers.

The initial benchmark harness invocation pointed at an empty diagnostic directory and failed healing catch-up. That setup error is retained separately; both reported comparisons used the intended copied databases. A first render assertion also used truncation rather than ceiling for fractional pixel dimensions and was corrected. An optional icon-gallery invocation was separated from toolbar lifecycle validation; no artwork was changed.

## Delivery scope

Source-tree backups were verified before integration. App, profiles and private research are backed up and hash-verified before graceful local replacement. Runtime/export privacy scans are reviewed against exact file hashes; synthetic test-network constants and the vendor link-local discovery constant are distinguished from personal addresses. Local guidance remains outside Git publication and every package.

Physical multi-monitor DPI transitions and live-game acceptance remain untested and separate from the native synthetic checks. Published releases, installers, download site, Store submission, application/tray artwork, signing keys, WSL configuration and Sandbox remain unchanged.
